# Verification

Read only the relevant section. The entrypoint controls execution budgets, context renewal and dispatch; this reference preserves detailed verification rules.

## The Laws (earned in production — each one cost something)

**Law 1 — The orchestrator is fallible; verify premises before destructive acts.**
Incident: an orchestrator concluded live checkpoint tables were "inert" from `max(thread_id)` over a *text* UUID column — a lexicographic max that says nothing about recency — and queued an archive that would have destroyed running production state. An independent QA agent overturned the premise minutes before execution. Rule: any archive/drop/migration/teardown gets its *premise* re-derived by an agent who didn't form it, from raw evidence. Prefer reversible forms (rename/archive-schema over drop; disable over delete) even after verification. Corollary: a compaction/handoff summary is itself an unverified premise — re-derive branch/merge state from live git before committing on a resumed session's word.

**Law 2 — The environment silently discards configuration; verify guarantees empirically, never structurally.**
Incidents: a connection pooler (Supavisor) silently dropped `options=-csearch_path=...` startup parameters, rendering a schema-isolation control inert while every health check stayed green; `uv pip compile` preserves existing pins when the output file exists and fresh-resolves when it doesn't; GitHub's `required_approving_review_count: 0` silently disables the review machinery a rule appears to enable. Rule: any guarantee mediated by infrastructure must be proven by observing the *live effect*, not by reading the config that requests it. Corollary: the fix must sit at a layer the environment cannot drop — an in-session statement beats a startup option. **Corollary 2b — prove the guarantee under the role the application actually uses.** `REVOKE ... FROM PUBLIC` does not bind the table owner and PostgreSQL never permission-checks a superuser, so seven tables' append-only guarantees were inert while the app connected as owner; a `DELETE` succeeded against a table whose privileges forbade it. The one control that held was a trigger, because a trigger binds regardless of role. A privilege-based guarantee tested as superuser proves nothing.

**Role-scope corollary (S01 continuation, 2026-09-06): a signed transaction context proves freshness, not the caller’s authority to choose its workspace.** Test that the binding function authorizes the actual connecting login before minting the context, and that the production connection uses that login. Rehearse migrations with the real predecessor security-definer bodies; dummy permissive bodies can hide role and schema failures. If the original baseline is missing, record the reconstructed portion and keep full-chain qualification open.

**Law 3 — Success output must assert the postcondition, not completion.**
Incident: a deploy-prep script printed two success lines while its `setup()` no-op'd against the wrong schema. Rule: every script/gate/probe that reports success must verify the *resolved state* and fail closed otherwise. Extensions: a readiness value computed once at boot is a snapshot, not a check (3b); a verdict past its staleness bound reads un-ready (3c); and for data migrations the postcondition ladder is *structural parity → copy-count identity against recorded preflight numbers → a live-run probe with the source proven frozen* — the last rung (source count unchanged while the new path grows under real traffic) is the only one that proves the cutover rather than the copy (3d).

**Law 4 — Fake-fidelity: every external-SDK seam needs one test against the real client.**
Incident: an agent added a `usage` kwarg asserted by 19 tests — all faking the client one level below the seam; the real SDK's method had no such parameter and every live model call crashed. Rule: one test per seam constructs the REAL pinned client through the production code path. Watch shape (`ChatResult` vs `LLMResult`) and watch *library value-laundering*: a pinned client that back-fills absent fields with zeros can convert "no evidence" into "affirmative zero" one level below your check. **Corollary 4b — installed-version check (2026-09-07):** before accepting a test report, compare the executing environment's installed distribution versions with the active lock and record the imported source path — a correct lock file does not update an old virtual environment. Reproduce SDK-dependent controls with the actual locked client before assigning a release verdict.

**Law 5 — Deterministic gates before subjective judgment.**
Hard-loss pre-checks run before the LLM reviewer; no model opinion overrides them. In orchestration: file lists, pairwise overlap, parent SHAs, byte-identical merge order, protected paths, lock freshness — before any subjective review. Watch for judge anchoring (a reviewer returning the same score every time is not discriminating).

**Law 6 — Pin the toolchain; CI installs what production installs.**
Floating dev tools broke CI on upstream releases while production stayed green on the hash-pinned lock. Exact-pin dev tools, semver-guard runtime deps, CI consumes the production lock artifact.

**Law 7 — A test that greps the whole artifact pins nothing. Scope assertions to the block that must carry the property.**
Incident: a migration's re-key assertion was satisfied by sibling sections even when the copy didn't re-key; fixed in §3, immediately recurred in §4. Extension: in layered defenses, *position the poison where only the guard under test can stop it* — a charset assertion whose control characters sit past the length clamp is satisfied by the length clamp alone. When a dev self-reports replacing a vacuous test, verify the replacement bites. **Extension 7b — verify a guard by REMOVING it, not only by poisoning past it.** The orchestrator mounted a control, wrote a test proving refusal, watched it pass, then unmounted the control and watched all tests pass anyway: a pre-existing weaker guard refused first, so the stronger one could have been deleted entirely with a green suite. **Two controls in series means the later one is untested until the earlier one is removed.** Delete-the-guard is the cheap negative control and it catches what poison-positioning misses. **Extension 7c — assert against the PARSED artifact, not its source text.** Twelve unit tests asserted a button's `background`, `color` and `font-size` via `assert.match()` on raw HTML and all twelve passed while every one of those declarations was being *discarded by the browser*: the component interpolated a font stack containing `"Segoe UI"` into a double-quoted `style` attribute, and the embedded quote terminated the attribute early. The bytes the test grepped for were present; they had simply stopped being part of any attribute. **A string-level assertion cannot see a syntax error that changes meaning** — parse the artifact the way its consumer will (HTML tokenizer, JSON parser, YAML loader) and assert against the parsed value.

**Law 8 — Mutation-test the guards on anything that will touch production data.**
38 mutations on one migration → 17 initial survivors including a verification gate rewritable into a tautology. For governance *scans*, also mutation-test the loosening direction (over-harvest controls): pin the false-positive boundary too.

**Law 9 — QA findings are claims; the fix round's first act is to reproduce them.**
Incident: a re-gate reported a P2 fd leak with a measured repro. The fix-round agent reproduced it first and found the measurement was an artifact — the blackhole listener lived *in-process*, so every accepted connection added a server-side fd to the same process's count; a true out-of-process blackhole leaked nothing. The prescribed restructure was built, measured, and shown to move nothing. Rule: a QA repro's *measurement method* is part of the claim. Ship the stronger regression test anyway when the class of gap is real; record the refutation so the finding doesn't resurface.

**Law 10 — A structurally green knowledge graph is not semantically green.**
Incident: a 298-entity research graph passed schema, source, and connectivity gates while still carrying cross-predicate mirror edges, reversed risk/control semantics, unsupported firm-observation metadata, and one true duplicate. Rule: before synthesis, run a fresh semantic gate that attacks one-fact/two-direction pairs, predicate domain/range, source-to-metadata traceability, and conceptual duplicates. Minimum degree counts only distinct, live, non-self relations; removing unsupported edges must trigger re-validation rather than relation padding.

**Law 11 — The slice that BUILDS a control must also MOUNT it. Splitting build from wiring produces finished, tested, unreachable code.**
Incidents (four in one project, each caught by a different gate): a routes module left as a six-line stub, so activation and deactivation had passing domain tests and no route; three platform controls — a disclosure gate, a config-driven branch, a notification recorder — shipped green with **zero callers**, so a direct API call skipped the gate entirely; a route that reached a stub returning a hardcoded refund while the real service, twenty passing tests deep, had no production caller *and* wrote to a different store than the command that fed it; five UI screens each defaulting to their own empty service, so the one that could never find a policy returned "not found" forever. Every instance shared one cause: **the mounting service was NO-GO for the slice that built the thing being mounted**, and every agent obeyed its boundary correctly. The boundary was wrong. Rules: (a) ownership boundaries must not separate a control from its call site — if they must, the wiring is its own slice dispatched in the same wave, never "someone else will"; (b) a slice's definition of done is **a request that reaches its code through the real seam**, not a passing unit test; (c) the orchestrator's smoke boots the artifact the way the operator will (`npm start`, not a hand-constructed harness) — constructing the server yourself with different options is how you prove a screen works that is dead in production.

**Law 12 — A gate that grades a registry passes; only a gate that grades the artifact bites.**
Incident: in one build every gate keyed to a declared list reported green while the rendered product was broken. The contrast gate graded a token table, not the emitted CSS, so cyan shipped as body text at 3.32:1. The conformance gate hand-rolled the flow list two lines after a comment forbidding exactly that, so no new screen was ever covered. The hex-literal gate cited "no hex in a **screen** file" and scanned only the components directory. Nothing asserted that a served page contained the script whose hash the CSP pinned. Rule: for every gate, ask *what would have to change for this to go red* — if the answer is "an entry in a list I also control," it is grading the declaration, not the thing. Point at least one assertion at the rendered/served/compiled output. Corollary: **a fixture smaller than production's smallest real case proves nothing about production** — two tests pinned a last-vehicle rule with one seeded vehicle where the demo seeds two, and the rule was wrong for every sequential removal. **Extension 12b — reviewer-side (2026-09-18): a score that rises when the reviewer looks at less is grading the review, not the artifact.** Any scoring instrument a wave builds gets an adversarial case where the reviewer withholds effort; "not verified" scores 0 and keeps its full weight with coverage reported separately, and applicability is a property of the artifact class, never of the review. **Extension 12c — rendered media and prose (2026-09-15/16/19):** assert the viewer-facing property — rendered box ratio via `getBoundingClientRect`, fraction of the picture shown, the content not its container (a homography that maps a bounding box, `object-fit: cover`, or a presentational `height=""` all hide a wrong box as a plausible crop); run the adversarial gate only after real media has landed (a green gate on placeholders is a claim about placeholders); include a keyboard walk (Tab through every focusable, then compare geometry to a clean load — script-positioned viewports must be `overflow: clip`); report a Lighthouse score with its invocation and throttling config; and in content-vault waves grep every asserted timestamp back to a machine-readable stamp inside a cited document — a time that exists only in `stat` output or a heading is not a claim any source makes.

**Law 13 — A mutation probe snapshots BYTES before it mutates; a hash alone cannot restore.**
Incident: an adversarial QA agent popped a record entry to prove its gate red, recorded only the pre-probe SHA-256, then reconstructed the deleted object from memory — restore failed byte-identity and the session died mid-recovery, leaving the tree mutated. Recovery succeeded only because the session DB persists agents' literal `write_file` arguments. Rule: before any transient probe, `cp` the target aside; restore is *copy back*, verified by SHA against the snapshot — never by reconstruction. Corollary: the session DB (`messages.tool_calls`) is the authoritative recovery source for every file an agent wrote, including contents orchestrators never saw. *(Lineage note: this law existed as "Law 11" in a forked staging copy; renumbered 13 in the 2026-08-28 lineage merge so the build-and-mount Law 11 and registry-gate Law 12 keep their numbers.)*


## Verification details (apply within the bounded workflow in SKILL.md)

1. **Plan only independent, disjoint parallel slices.** Verify ownership by file path and shared mutable state; sequence shared files, dependent integration steps, and work that can invalidate another slice's evidence. Reserve independent QA capacity before filling producer slots. Stacked work branches start from an integration base of QA-passed branches.
2. **Dispatch independent dev agents in parallel** with self-contained prompts: context, goal, acceptance criteria, ownership + explicit NO-GO paths, safety rules, verify commands, report contract. **Brief the property to restore, not the code change to make** — devs honoring the property over the prescription have out-reasoned the brief repeatedly, confirmed by QA. Tell agents to verify orchestrator-supplied facts and to STOP at ownership boundaries.
3. **QA gate (separate agent, fresh eyes, adversarial mandate).** QA executes its own scoped behavior checks once against the candidate it grades — *assert which tree the package resolves to first; the stale-venv trap has caught the orchestrator too*. Run all repository-required checks. Add adversarial probes and the relevant real-integration checks; expand to a broad suite when changed behavior or integration risk warrants it. PASS/FAIL per slice; FAIL blocks. "PASS with defects" is a normal verdict — rank and route them. When QA's mandate is read-only and its scope is the untouched remainder of the repo, run it CONCURRENTLY with dev — enforce with a written "you may not modify a single line of code, findings go in the report" clause. When two slices build against one contract in parallel, gate the SEAM explicitly, not just each side: diff the keys one side emits against the fields the other actually reads, and hand-check any field one side derives rather than receives. **Dispatch-side counterpart (2026-08-28b): when one slice DEFINES a new contract and another CONSUMES it in the same wave, the orchestrator pins the exact signature verbatim in BOTH briefs, the consumer tests against its own local double, merge order is definer-first — and the gate's headline mandate is the one live pairing neither dev ran (consumer through the real composition against the definer's real implementation).** **An error message names one instance; the catalog names the class.** Two dev agents independently reported a schema failure as "fails on table X" because that is what the error said; the QA gate queried the system catalog against the registry and found **four** tables with the same defect — and the generating loop had no `ORDER BY`, so *which* one errored first was arbitrary and fixing the named one would have surfaced the next. Where a failure is generated by a loop, a rule, or a registry, QA enumerates the population rather than trusting the first exception. **Spend the stronger model on the gate, not only on the build:** the same run's dev agents also mis-diagnosed a circular dependency as a one-way cascade, which the gate refuted from `grep`-level evidence. **Content seam (2026-09-18/19):** the seam gate applies to prose too — when one slice's output is a *pointer* to state another slice changes, gate the pointer after both land or serialize them; cross-page references in a parallel wave cite by heading text or anchor, never by ordinal, and the orchestrator greps `§\d` across the assembled tree before the gate, fixing the section drafts in the same edit as the assembled file.
4. **Fix rounds go back to the same dev** with findings verbatim, subject to Law 9: reproduce first, refute if refutable, fix what survives. Negative-controlled regressions, then re-gate. Grant cross-boundary ownership explicitly per round.
5. **Micro-rounds for small post-gate defects:** tight single-file briefs; orchestrator does the final verification itself instead of a third full gate — proportionate process beats ritual process.
6. **Integrate QA-accepted source before final integration acceptance.** Run the orchestrator's behavioral smoke on the real seams of that merged tree while QA and report preparation proceed on separate outputs.
7. **Merge queue:** parents verified, byte-identical tree both orders, exact operator commands, new env vars / operator steps named up front, order chosen so the trunk is never transiently self-inconsistent.
8. **Persist probe suites**; retire superseded probes explicitly when a contract deliberately flips.

**Evidence, custody, and closeout.** Reuse existing evidence only when code, inputs, toolchain, configuration, rubric, and relevant agent/artifact/service identities match the claim; otherwise rerun the changed behavior or real integration risk. After later metadata- or documentation-only changes, verify identity and integrity instead of replaying unchanged behavior. Consolidate artifact custody once per accepted candidate and retain the canonical receipt or receipts required by each task/attempt contract; preserve failed evidence and negative results unchanged, and batch closeout after acceptance. Limit the shared custodian to Git and ledger mutations; let QA and report preparation proceed on separate outputs. Report a blocker when first known with its owner and evidence, reuse measured timings, mark unknown time as unknown, and add no tracking system solely for the retrospective. A tool that writes a fixed body makes every post-write append invisible to its own receipt (2026-09-19): when the contract requires content the writing tool cannot emit, extend the tool or stop citing the receipt as integrity proof — never both hand-append and cite it. Stop when the explicit completion criteria are met.


## Triage Before New Slices

When gates disagree or tests loop: stop generating slices, isolate the failing layer (static/config → runtime health → task delivery → tool lifecycle → canonical audit evidence → semantic response → gate truth → release decision), patch only the proven-defective layer. Cheap canonical evidence beats a rerun.


## Holdout / Eval Hygiene

Fresh-context grader, zero implementation context; orchestrator and producers never see scenario contents; results-only commits; scores back, never cases. Honor a NO-GO by filing remediation. What a reviewer actually grades may be a *docstring* — dead governance code with a confident docstring is what anchors them.
