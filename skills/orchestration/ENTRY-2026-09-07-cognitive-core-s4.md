# Cognitive Core S4 orchestration lessons

Staged proposal only. Preserve the existing staged and registry histories; publication is separate.

1. **Pin the complete imported runtime.** The S4 controller initially described a 1,033-test native run using the candidate SHA and unchanged cognition package/tests. Two preexisting uncommitted support helpers were also imported. The corrected evidence names that overlay and limits the claim. A separate reviewer archived committed scripts and reproduced the component suite without the overlay. Future gates must hash every imported support module/configuration and compare those bytes to the candidate, or use an exact committed archive with a declared fixture closure.
2. **Search every declared local artifact store before claiming absence.** An empty downloads directory and unloaded catalog do not establish that model bytes are absent. A reviewer found the pinned GGUF in LM Studio's hidden bundled-model directory and verified its size and SHA-256. Physical presence, provider loading, model approval and semantic verification remain separate facts.
3. **Validate measurement identity at each sample.** A capability advertisement does not establish which retrieval condition served a query. Label a degraded vector/fused packet as unavailable for that condition; do not score the fallback's lexical result as vector quality. Core latency includes fusion, eligibility, deduplication and budget work, with model time recorded separately.

These lessons strengthen existing source-identity, live-effect and seam-verification rules. They do not authorize new tools, model adoption, live cutover or tracker acceptance.
